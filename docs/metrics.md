# 评测与健康度监控：如何证明记忆库真的在创造正收益

没有客观消融对照与静态守卫，工程知识库极易陷入三种假象：
1. **文档越攒越厚，以为沉淀扎实**——实际可能只是检索信噪比恶化、定位根因所需轮数变多；
2. **偶发秒答难题，以为记忆生效**——其实前沿模型凭预训练通用物理常识就能答出；
3. **定期蒸馏持续出 Diff，以为系统健康**——若缺少真值抽检，可能正在批量抹平关键硬件个体边界。

---

## 一、 零 Token 机械守卫（`aml check`，每次提交与蒸馏必跑）

在消耗评测算力之前，`python3 scripts/aml.py check --repo <path>` 以 `0 token` 成本硬性卡死结构退化：

| 检查项 | 机械阈值 / 规则 | 拦截哪类退化 |
|---|---|---|
| **控制面预算** | `0_control/{rules,INDEX}.md` 及 `hosts/*/env.md <= 4 KB` | 防止全局常驻层膨胀挤占任务上下文 |
| **产品热索引上限** | `MEMORY.md <= 200 行` 且 `<= 25 KB` | 逼迫具体细节下沉至 `1..4` 层按需读取 |
| **Borges 导航压缩比** | `size(1_theory + MEMORY.md) / size(transcripts + 2_calibration + 4_anomalies) <= 0.30` | 防止 `1_theory/` 沦为冗长原文摘抄（「地图大于国土」） |
| **元数据与证据链** | `verified` 资产/异常必含 `id`、合法 `status`、`applies_to` 与可解析的 `evidence` ID | 杜绝无版本边界、无原始证据支撑的悬空结论 |
| **`stale` 零残留** | 凡标为 `status: stale` 的条目 ID 严禁出现在 `MEMORY.md` 或 `INDEX.md` | 从结构上消灭注入层过期规则污染 |
| **租户与机密隔离** | 阻断 `tenants/A` 引用 `tenants/B`；拦截私钥、Token 与内嵌凭证 URL | 守住多客户合规与信息安全底线 |

## 二、 五组消融对照实验（定位哪一层真正在出力）

从真实已结案历史问题中抽取 `30–50` 道代表性题目（格式见 `templates/product/eval/cases.jsonl`），在全新无历史会话中跑五组对照：

| 对照组 | 允许访问的记忆范围 | 检验核心假设 |
|---|---|---|
| **A0 裸模型基线** | 不挂载任何项目记忆 | 剥离模型预训练自带的通用科学/编程常识 |
| **A1 仅搜事实底座** | 仅允许 `aml search` 检索 `transcripts/` | **核心基准线**：检验结构化分层相比直接全文搜原始工单/实验日志到底提升了多少 |
| **B 单点基线与排故层** | `transcripts/` + `2_calibration/` + `4_anomalies/` | 检验单件资产安全包线、标定 SOP 与排故记录的直接收益 |
| **C 完整双轴结构层** | B + `1_theory/` + `3_skills/` + `MEMORY.md` | 检验机理图谱、按需 Skill 与热路由是否显著降低跨材料推理轮数与 Token |
| **D 多轮离线蒸馏后** | 在 C 基础上历经版本切换与多轮 Dreaming 四向反哺 | 检验离线蒸馏是在精准淘汰 `stale` 噪音，还是在误伤有效细节 |

### 高区分度出题比例建议
1. **反直觉排故陷阱题（`>= 25%`）**：表象极像控制/解算软件发散，真实根因在供电纹波混叠、传感器个体漂移或机械装夹耦合。
2. **版本升级 / 备件切换失效题**：旧补偿表或旧默认模式在新固件版本、更换新序列号模块后不再成立甚至放大误差。
3. **安全包线拦截题**：调参请求暗中越过某在役资产的饱和阈值或瞬时损坏硬极限，考察是否前置阻断。
4. **负结果避坑题**：针对团队曾实测证伪（`status: refuted`）的无效方案，考察是否主动引用历史记录劝阻重复投入。
5. **现场口径隔离题**：同一技术指标在特定客户现场（`tenants/<code>/`）具有特殊验收定义或停机窗口限制。

## 三、 线上运行健康度核心指标

| 指标 | 定义 | 目标方向 |
|---|---|---|
| **决策盲评均分** | 三档计分：`0`（错/踩安全红线/误引 `stale`）、`0.5`（方向对但漏查版本号或资产 ID）、`1`（判断、依据与最小验证动作全准） | `↑` |
| **根因定位轮数 / 单题 Token** | 从问题描述到给出正确排他实验的平均交互轮数与上下文开销 | `↓` |
| **`stale` 恶性误引率** | 将已过期（`stale`）结论当作现行有效规则引用的会话占比 | **`-> 0%`（生命线指标）** |
| **`refuted` 负结果拦截率** | 遇到历史已证伪方向时，主动引用 `refuted` 条目避免重复实验的比例 | `↑` |
| **异常一次复现率** | `4_anomalies/open/` 中的待破案单，换另一人按记录能否一次复现异常 | `> 85%` |
| **四向反哺闭环率** | `resolved` 结案单中完成机理边界、标定 SOP 或操作 Skill 修补的比例 | `↑` |
