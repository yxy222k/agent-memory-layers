# 评测：怎么确认记忆库真的有用

没有对照评测，记忆库很容易陷入三种自我感动：

1. **文件越来越多，觉得沉淀很厚**——其实可能只是检索噪音变大、找一条真结论更慢了。
2. **偶尔一次秒解难题，觉得系统神了**——可能是前沿大模型本来就懂那条物理定律。
3. **Cronjob 每周都在出 Patch，觉得系统很健康**——如果没人核对真值，它可能在批量把正确细节“概括”错。

---

## 一、 五组消融对照（找出哪一层真正在干活）

拿一批**已结案、有真值依据的真实历史问题**（30–50 题足够），在全新会话中跑五组对照：

| 组别 | 挂载内容 | 检验什么 |
|---|---|---|
| **A0 裸模型基线** | 无任何项目记忆，仅靠模型预训练知识 | 区分「模型本来就会的通用物理/编程常识」与「项目私有经验」 |
| **A1 仅搜事实底座** | 只允许检索 `transcripts/` 原始记录 | **关键基线**：检验花精力做上层提炼，到底比直接 `rg` 搜原始工单/实验日志强多少 |
| **B 单点经验层** | `transcripts/` + `2_calibration/` + `4_anomalies/` | 检验器件基线档案、标定 SOP 与排故记录的直接贡献 |
| **C 全结构层** | B + `1_theory/` + `3_skills/` + `MEMORY.md` | 检验机理图谱（Wiki）、按需 Skill 与常驻索引是否降低了跨文档推理成本 |
| **D 离线蒸馏后** | 在 C 基础上经过多轮 Dreaming 纠错与跨层反哺 | 检验离线蒸馏是在消除过期污染，还是在损伤细节 |

> **经验参考**：单份记录里直接能搜到答案的问题，A1 往往已经够好；只有**需要跨多份实验综合判断、涉及器件个体差异或排故反直觉陷阱**的题，B / C / D 才会拉开显著差距。如果 C 相比 B 没有提升且 Token 消耗更高，说明 `1_theory/` 写成了臃肿的原文摘抄。

## 二、 题集怎么出

见 [`../templates/eval/cases.jsonl`](../templates/eval/cases.jsonl)。出题遵守四条原则：

1. **只从真实踩过的坑里抽**：编出来的题测的是出题人的想象力，不是系统记忆力。
2. **每题必须能回溯到 `transcripts/` 真值**：追不到原始记录或实测数据的题作废。
3. **重点覆盖五类高区分度题型**：
   - **排故陷阱题**（占 25%+）：表面像算法/软件崩了，根因在光源漂移、探头更换或机械载台。
   - **跨版本/换件失效题**：旧补偿表或旧做法在新软件版本、换新批次器件后反而放大误差。
   - **器件个体边界题**：操作参数是否触碰了当前台架光谱仪的饱和/瞬时过载阈值。
   - **多材料机理综合题**：需要结合 `1_theory/` 机理公式与 `2_calibration/` 实测曲线做定量判断。
   - **现场口径题**：同一个词在不同客户现场或不同软件模块里含义不同。
4. **三档盲评**：`0`（错 / 踩红线 / 引用过期结论）、`0.5`（方向对但缺关键前置检查如未问版本号或硬件 SN）、`1`（结论、依据、下一步动作均准确）。

## 三、 核心监控指标

### 通用健康度指标

| 指标 | 定义 | 目标方向 |
|---|---|---|
| **决策得分均值** | 评测集盲评均分 | ↑ |
| **定位轮数 / 单题 Token** | 到正确排故动作的平均交互轮数与消耗 | ↓ |
| **`stale` 误引率** | 把已过期（`stale`）记忆当现行有效结论引用的比例 | **↓（生命线指标）** |
| **负结果（`refuted`）有效拦截率** | 遇到曾被证伪的方向时，主动引用 `refuted` 记录劝阻重复试错的比例 | ↑ |
| **导航压缩比** | `size(1_theory + MEMORY.md) / size(transcripts + 2_calibration + 4_anomalies)` | `< 0.3`（地图必须远小于国土） |

> 注意区分 **`stale` 误引**（坏事：拿旧版本的失效规则指导现行系统）与 **`refuted` 引用**（好事：提醒研发“这个滤波方案上个月试过不行，别重做一遍”）。

### 研发与实验场景专项指标

- **重复无效实验率**：新开的实验或排查动作中，其实历史记录里已经测过（含负结果）的比例 ↓
- **异常复现成功率**：`4_anomalies/open/` 中的悬而未决问题，换一个人按记录能否一次复现 ↑
- **标定留证完整率**：入库器件与样品测量记录中，暗谱、过载阈值、光路照片、截图等必检项齐全的比例 ↑
- **跨层反哺闭环率**：`resolved` 结案异常中，实际触发了 SOP 增补、器件档案刷新或机理假设修正的比例

### 现场交付场景专项指标

- **首次排故命中率**：一次远程会话或一次上门即定位根因的比例 ↑
- **跨租户口径零事故**：泄露其他客户信息或套错现场验收判据的次数 `= 0`

## 四、 停机整顿信号（熔断线）

出现以下任一现象，暂停盲目往库里塞新内容，先跑一次结构清理：

- **`stale` 误引率 > 15%**（说明换件/发版后的失效扫描断档了）
- **`MEMORY.md` 突破 200 行 / 25KB** 且无法下沉（说明索引层混入了具体业务细节）
- **`1_theory/` 总字数超过底层实测与异常记录总和**（Borges 地图病，抽象度归零）
- **超过 30% 的 `open` 异常因缺少硬件 SN、软件版本或原始数据路径而无法复现**
