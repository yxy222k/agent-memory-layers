# 怎么知道它有用

没有评测，这套东西就只能靠"感觉变好了"。三种常见的自我欺骗：

- 笔记越写越多，于是觉得知识在积累（其实可能只是检索变慢）
- 偶尔答对一次复杂问题，于是觉得有效（可能是模型本来就会）
- 整理环节每天在跑，于是觉得系统健康（它可能在制造错误）

## 四组对照

最省事的做法是**回放式对照**：拿一批已结案的真实问题，让四组配置各答一遍。

| 组 | 配置 |
|---|---|
| A 基线 | 无记忆，每次全新会话 |
| B 笔记 | 只有 ② |
| C 笔记 + 地图 | 加 ③ |
| D 全量 | 加离线整理 |

四组的差别能直接告诉你：**到底哪一层在起作用**。很多团队到这里才发现，
花最多力气建的地图层（C 相对 B）几乎没贡献，而真正有效的是老老实实的笔记。

> 现实数据参考：地图类表示的价值高度依赖任务。需要跨多份材料综合、需要判断或算术的题，
> 有地图明显更好；而大部分答案能在一份材料里搜到的题，地图没有增益。

## 题集怎么出

- **从真实问题里抽**，不要自己编。编出来的题测的是你的想象力。
- **答案必须能追溯到某条原始记录**，追不到的题不成立，删掉。
- 每 10 题里放 2–3 道**陷阱题**：表面像 A，实际是 B。这类题最能区分"有没有真记忆"。
- 规模：一个域 30–50 题就够，两个人两小时能评完。

评分用 0 / 0.5 / 1 三档，两人独立评再校准。别用"感觉对"。

## 看哪几个数

### 通用

| 指标 | 定义 | 方向 |
|---|---|---|
| 决策正确率 | 人工评分均值 | ↑ |
| 定位轮数 | 到正确答案的平均对话轮数 | ↓ |
| token / 题 | 单题消耗 | ↓ |
| **stale 引用率** | 引用了已失效记忆的比例 | ↓ |
| 库规模曲线 | 字符数随时间的增长 | 平稳 |

`stale 引用率` 是最容易被忽略、但决定这套系统可不可信的那个数。它高说明整理环节没跟上，
这时补笔记只会让情况更糟。

### 服务型场景（对外支持）

- **首次修复率**：一次上门/一次会话解决的比例
- **二次上门率**：同一问题 30 天内复发
- **知识复用率**：解决时引用了既有记忆的比例

### 研发型场景

- **重复实验率**：新实验里已经做过的比例（含已知的负结果）
- **假设收敛速度**：`open` → `confirmed/refuted` 的平均天数
- **记录完整率**：关键参数缺失的实验比例

研发线的记忆里，最容易缺的是**负结果**——"这个我们试过了，不行"。它通常只存在于某个人的
记忆和一次周会 PPT 里，人一走就归零，然后半年后有人再试一遍。

## 什么时候该停下来

出现下面任一情况，说明结构在退化，先修结构再加量：

- `stale 引用率` > 20%
- 注入层逼近上限，且下沉不掉（说明 ② 没有分层）
- 地图总量超过它索引的材料总量
- 一篇笔记里出现三个以上互不相关的主题
