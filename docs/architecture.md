# 双轴记忆架构：业务四域 × 加工四阶

## 为什么单维分层不够用

纯软件/纯文本场景下的 Agent 记忆（如 Anthropic《The components of agent memory》），只需要沿着**信息浓缩度**切一刀：`原始流水 → 单点笔记 → 导航 Wiki → 常驻提示词`。

但一旦进入**软硬件结合、光电/精密测量、现场交付与研发并行**的项目，单维模板很快就会卡壳：

- **麦克斯韦/干涉相位方程**和**某台光谱仪的暗谱 counts**不是同一种知识：前者几乎永不过期，后者换一台设备或老化半年就变了。
- **串口指令、`hdf5` 存储格式、对外 PPT 脱敏规范**属于「怎么操作工具」的程序性记忆，平时根本不该占推理上下文，连设备或出报告时按需挂载即可。
- **排故记录**在未破案时没有机理可写，只能保复现；一旦破案，它又会反过来推翻三个月前的实验结论、补齐漏掉的标定项，甚至修正物理仿真模型的边界假设。

所以这套系统采用**正交双轴结构**：

- **横轴（存什么、半衰期多长）**：按硬科技工程本体切为**四个业务域**。
- **纵轴（怎么浓缩、何时加载）**：按上下文成本与证据链切为**四个加工阶**。

## 一、 横轴：四个业务域

| 域 | 目录 | 放什么 | 半衰期 | 生产与审阅方式 |
|---|---|---|---|---|
| **① 科学机理与模型** | `1_theory/` | 物理/数学定律、文献调研、知识图谱、建模与仿真边界 | 极长（仅当模型前提被实测证伪时修订） | 最前沿大模型多 Agent 并发（一人一页 + 共享日志）+ 人工共同审阅 |
| **② 标定规程与器件档案** | `2_calibration/` | **SOP**：标定/验证/样品测量必检项；**Asset**：单器件实测基线（漂移表、暗谱、过载阈值） | SOP 长；Asset 绑定**硬件 SN / 校准期** | 人定规程；次级执行模型按强 Checklist 核对入库 |
| **③ 操作技能（Skill）** | `3_skills/` | 设备连接/串口指令、软件源码与 CLI、数据存储模板（`csv/hdf5/pcap/json`）、报告脱敏、办公自动化 | 中（随工具链与软件版本演进） | 封装为按需触发的 `SKILL.md` + 脚本；**密钥/凭证绝不入库** |
| **④ 异常与排故账本** | `4_anomalies/` | **Open**：悬而未决但随时可复现的异常包；**Resolved**：阶段性归因与对前三个域的推翻/修正记录 | 动态（驱动前三个域演化的发动机） | 在线轻量抓复现快照；结案后由离线蒸馏触发跨层反哺 |

### 第二层为什么要拆成 `sops/` 和 `assets/`

现场和实验室里最常见的混淆，是把「测试动作」和「单台硬件的脾气」写在一起：

- **规程（`2_calibration/sops/`）**回答「拿到一类器件必须测什么」：例如拿到 1310nm SLD 光源，必须测高低电流下的中心波长漂移；拿到光谱仪，必须测暗谱 counts、饱和阈值、瞬时过载阈值、波长标定表与积分档位；测样品必须留装置照片与上位机截图。
- **档案（`2_calibration/assets/`）**回答「编号 `#SLD-1310-03` 这支光源实测漂了多少」。一旦更换探头或光源，SOP 不变，但当前会话引用的 Asset 档案必须切换。

## 二、 纵轴：四个加工阶（控制检索成本与污染）

```text
④ 常驻注入阶  AGENTS.md + MEMORY.md   每次会话必载，硬上限 ≤200行/25KB（当前硬件SN + 版本 + 红线 + 索引）
③ 结构导航阶  1_theory/ + 3_skills/   跨材料综合图谱（Wiki）与按需挂载技能（Skill），总体积小于底层材料
② 判断与基线  2_calibration/ + 4_anomalies/  带证据链与状态机的规则、器件档案、异常复现包与归因结论
① 事实底座阶  transcripts/            原始实验记录、工单、会话流水、多模态伴生卡；只追加、不改写
```

**核心铁律：不跳阶、不篡改底座。**
第 ① 阶是离线纠错判断「某条结论对不对」的唯一真值。文档记录意图，原始记录记录事实；一旦原始记录被顺手润色，纠错就会退化成循环论证。

## 三、 两阶段写入门槛（兼顾敏锐度与严谨度）

Anthropic 的对照实验证明：**在任务进行中给强模型设过于死板的写入格式与过滤规则，反而会大幅削弱记忆收益**——事发当下没人能完全预知未来，过严的前置门槛要么让人懒得记，要么逼模型为了填表而脑补机理。

因此写入分两档，**宽进严升**：

1. **现场/在线速记（`open` 异常 / `hypothesis` 草稿）—— 低门槛抓信号**
   - 只要满足：**屏幕/系统里直接查不到** + **未来可能再遇到** + **附带原始证据或复现快照**，即可入库。
   - **不强求**当场写清底层物理机制，允许只记「现象 + 有效临时动作 + 硬件 SN / 软件版本 + 数据路径」。
2. **固化/晋升（`resolved` 结案 / `verified` 规则 / `1_theory` 入图）—— 高门槛防污染**
   - 必须有 **≥2 次独立证据**（或明确的可复现归因实验）。
   - 必须写明**机制判断**、**适用版本/硬件区间（`applies_to`）**与**反例 / 失效边界**。

### 状态机：把「证伪的负结果」和「过期失效」彻底分开

- `hypothesis` / `open` —— 待验证假设或未解异常，必须附带「可复现条件」或「最小验证方法」。
- `verified` —— 已验证成立的因果、规则或已结案归因。
- `refuted` —— **已被实验证伪的假设（负结果）**。在研发线里，「这条路试过了不通」价值极高，**保留并允许正面引用避坑**，不计入失效引用。
- `stale` —— **曾经成立，但因软件升级、硬件换代或现场配置变更而不再成立**。只标 `stale` 不删除，从 `MEMORY.md` 移除；若后续会话仍当现行规则引用，计入恶性 `stale 引用率`。

## 四、 多模态数据与安全边界

### 照片、截图与大体积数据（`hdf5` / `pcap`）怎么进纯文本库

记忆库本身保持纯文本 Git 仓库，不直接塞几百 MB 的 `.hdf5`、`.pcap` 或大量原图。采用 **外部存储路径 + Markdown 伴生索引卡（Sidecar）**：

- 原件按 `3_skills/data-schema/` 的命名规范存入 NAS / 对象存储 / Git LFS。
- 在 `transcripts/` 中生成对应的轻量 `.md` 伴生卡，记录：硬件 SN 组合、软件版本、积分档位/关键参数、原件路径与校验值，以及**一两句光路状态描述或上位机截图关键读数**。检索与离线蒸馏读伴生卡，复现时按路径取原件。

### 三条安全硬红线

1. **凭证零落盘**：设备登录密码、SSH 私钥、Git 凭证、Lark Token **严禁写入任何一层 Markdown**。`3_skills/` 中只允许记录环境变量名（如 `$LAB_NAS_TOKEN`）或系统钥匙串调用方式。
2. **核心技术脱敏**：对外报告（PPT/文档）禁止暴露的核心算法参数、内部补偿表、特定光路结构，必须在 `AGENTS.md` 红线与 `3_skills/reporting/` 中双重声明，导出前自检。
3. **多租户物理隔离**：涉及多个客户现场时，检索必须通过 `scripts/search.sh --tenant <代号>` 限定目录范围，禁止跨租户跑全库裸 `rg`。

## 五、 两种记忆不要混

个人/通用 Agent 工作台（如 `agent-memory-nest`）管的是「**我怎么配合你干活**」（个人偏好、跨项目日程、通用工作流）；本仓库管的是「**这条产品线/研发线知道什么**」。

- 产品/项目仓库 `memory/`：放完整的双轴记忆库。
- 个人 Agent 记忆库：只放一句项目状态快照与指向本仓库的入口路径，不搬运任何具体标定值、客户口径或排故细节。
